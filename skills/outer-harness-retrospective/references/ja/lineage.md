# 関連するセッションの数え方

何回起きたかを数えるときは、同じセッションでの再試行や関連する記録と、別々のやり取りでの再発を、次のルールで区別する。

| 証拠 | 扱い |
| --- | --- |
| `source_ref` が同じ記録。セッション再開後に内容が変わった場合も含む。 | 参照元は同じものとして扱う。 |
| 明示された `parent` や `forked_from` の関係。間接的なつながりも含む。 | 同じ系統にまとめる。 |
| サブエージェントの証拠。 | 明示された関係か、共通形式に変換した親との関係から親を特定できる場合だけ、親の系統に含める。 |
| 同じソースインスタンス内で `source_ref` が異なる。 | 関係の情報が揃っており、与えられた文脈からも別々のやり取りと判断できる場合だけ、別々に数える。 |
| ソースインスタンスが異なる。 | 各応答が完全でも、別々のやり取りだと証拠から確認できる場合だけ、別々に数える。 |
| 同じプロバイダーの記録が、異なるソースインスタンスで同じ provider-source fingerprint を持つ。 | 同じ記録のコピーか、別々のやり取りかを証拠で区別できなければ、未確定として扱う。 |

証拠で確認できる関係のうち、数えるために必要なものだけをグラフにする。\
テキストや失敗が似ているだけで、記録をまとめない。\
必要な関係が欠けている場合や曖昧な場合は、不確実性を保ち、該当する情報源を独立した再発の確定的な証拠として数えない。

各系統内の再試行と、独立した系統の数を分けて報告する。
