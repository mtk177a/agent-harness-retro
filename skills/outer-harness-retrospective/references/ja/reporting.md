# 報告の要件

報告は依頼に合わせて構成し、直接の観測、所見、原因仮説、提案する解決策を区別する。

## 判断の記録

- **範囲**: 振り返った対象、どこまで証拠を確認できたか、結果に影響する読み残しや欠落を示す。

- **所見**

  証拠が裏付ける傾向と影響を説明する。\
  直接分かったことと、原因の仮説やまだ確かでない点を分け、解決策は所見に含めない。

- **証拠**

  観測、所見、判断から、後で確認できる形で元の証拠を参照する。\
  記録の `source_ref` と `verified_version`、該当する範囲のイベント、現在のハーネスで確認したファイルや仕組みと、その時点の内容を特定できる情報を示す。

- **判断**

  結果、誰がどの範囲で対応するか、どの仕組みを使うかを示す。\
  対応を選んだ理由や見送った理由、判断が変わり得る未確認事項も示す。

各提案に、次を含める。

- **変更**: 対象のリポジトリまたはグローバルなハーネスの構成要素を挙げ、どこにどんな最小限の変更を加えるかを示す。
- **理由:** 根拠となる所見と証拠、期待する改善、重要なトレードオフ。
- **引き継ぎ:** 検証方法、承認者、実装担当を示し、人名が示されていなければ役割名を使い、グローバルな提案では対象の構成要素の所有者を示す。

## 対応の仕組み

| コード | 使用する場合 |
| --- | --- |
| `memory_candidate` | 一時的かユーザー固有の知識を引き継ぐ場合。この分類は、メモリへの書き込みや独自の保存先の作成を許可しない。 |
| `global_instructions` | 実質的に異なる複数のリポジトリの文脈で、安定した行動原則が裏付けられる場合。 |
| `repository_guidance` | 1 つのリポジトリに固有の、永続的なエージェント向け知識の場合。 |
| `repeatable_skill` | 条件に応じて判断したり、複数の手順を踏んだりする作業を繰り返すのに、必要な手順がないか、その作業を扱う場所が適切でない場合。 |
| `hook_ci_rule` | 同じ入力に対して同じ判定ができ、条件を満たすよう自動で強制すべき場合。 |
| `canonical_project_change` | 正しさや知識が、プロジェクトの実装、テスト、正式な文書に属する場合。 |
| `one_off_action` | 局所的で一時的な対応で、永続的な仕組みを必要としない場合。 |
| `no_persistent_change` | 既存の仕組みで十分な場合、プロバイダーが管理する挙動である場合、または恒久的に変更するだけの理由がない場合。 |
