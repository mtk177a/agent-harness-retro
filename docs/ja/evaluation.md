## Skill を監査する

### 監査の記録

重要な Skill 監査では、次の情報を記録する。

| 項目 | 記録すること |
| --- | --- |
| 監査対象 | 監査した Skill のリビジョン。 |
| 作業ツリー | 作業ツリーの状態。 |
| 期待する動作 | Skill が何をすべきか。 |
| 利用者 | Skill が誰に影響するか。 |
| クライアント | Skill を使うクライアント。 |
| 指示の所在 | 関連する指示をどこで定めているか。 |
| 指示の権限 | どの指示が適用されるか。 |
| 証拠 | 何を観測したか。 |
| 所見 | 裏付けられた問題や有用なパターン。 |
| 代替案 | ほかに検討した対応。 |
| 不確実性 | まだ分かっていないこと。 |

### 監査の観点

その Skill に関係する観点だけを確認する。

- **担当する作業**: Skill が何をするか。
- **範囲:** どこに適用するか。
- **選択条件:** どのようなときに選ぶべきか。
- **併用:** ほかの Skill とどう併用するか。
- **情報源の優先順位:** どの情報源を優先するか。
- **証拠の質:** 証拠が所見をどの程度裏付けるか。
- **安全性:** 関係する安全上の懸念。
- **コンテキストの負担:** Skill が必要とするコンテキスト。
- **移植性:** 別のクライアントや環境での利用。
- **保守性:** 維持するために必要な作業。

英語の正式版と日本語参考訳は、別々に確認する。\
日本語参考訳は、英語版に変更がなくても、意味の対応と日本語の自然さを確認する。

### 監査結果

各論点を分類する。

| 分類 | 意味 |
| --- | --- |
| `change_required` | 変更が必要である。 |
| `no_change` | この論点について変更は必要ない。 |
| `separate_issue` | 今回の作業とは分けて扱う。 |
| `unverified` | まだ検証できていない。 |

重要な所見には、次の情報を添える。

- **証拠:** 所見を裏付けるもの。
- **影響:** なぜ重要か。
- **確度:** 証拠がどの程度裏付けるか。
- **反証方法:** 所見を否定できるか確かめる方法。

静的な監査だけで、モデルの実際の動作を確認できたとは扱わない。

## 評価方法を選ぶ

ケースを選ぶ前に、次の情報を定める。

- **変更の影響**: Skill のどの役割や動作に影響するか。
- **起こり得る失敗:** 何がうまくいかなくなる可能性があるか。
- **見分け方:** 何を観測すれば、その失敗が分かるか。

判断に必要な最小限の評価を選ぶ。

| 変更 | 基本の評価方法 |
| --- | --- |
| 文書、形式、意味を変えない文章の修正 | `static-only` |
| Skill の指示、出力仕様、安全上の境界 | `targeted-candidate` |
| 名前、説明、起動条件、関連する Skill や仕組みとの担当範囲 | `targeted-routing` |
| 既知の回帰、大きな設計変更、変更後の結果だけでは判断しにくい場合 | `baseline-comparison` |
| 特定のクライアントや環境への対応を主張する場合 | `target-environment` |

次の条件は、その結果で判断が変わり得るときだけ追加する。

- ベースラインとの比較。
- Skill を使わない条件との比較。
- 繰り返し実行。
- 別のクライアント。

編集のたびに全ケースを実行しない。

## ケースを用意する

### 定義ファイル

行動のケースでは Skill の動作を、ルーティングのケースでは Skill が選ばれて読み込まれるかを確認する。

| ケースの種類 | ファイル |
| --- | --- |
| 行動 | `skills/<name>/evals/evals.json` |
| ルーティング | `skills/<name>/evals/triggers.json` |

Agent Skills の実行可能な形式に従う。

| 用途 | フィールド |
| --- | --- |
| 定義の最上位 | `skill_name`、`evals` |
| ケースの識別 | `id` |
| 実行側への入力 | `prompt`、任意の `files` |
| 行動の採点 | `expected_output`、`assertions` |
| ルーティングの採点 | `expected_handlers` |

ケースの依頼文と入力ファイルには、実行側へ見せる情報だけを置く。\
判定条件と期待結果は実行側へ見せず、採点時に使う。

### テストデータ

識別子、リポジトリ、ハーネスの構成要素、セッションには合成データを使う。\
実セッションは、人が秘匿処理した後でもコミットしない。

### 定義の移行

既存の `evals.json` や `triggers.json` を移行するときは、影響する定義全体を一緒に移す。\
形式だけを移行する場合は静的な検証を行い、モデル実行は必須にしない。

## 静的検査を実行する

### リポジトリの検査

リポジトリのルートから実行する。

```sh
python3 scripts/check_repository.py
```

このスクリプトは、英語原文と日本語参考訳のファイルの対応、Skill のメタデータ、実行可能な評価定義、現在の短い評価記録を検査する。\
モデルは呼び出さない。

## モデルを使って評価する

### 評価計画

モデルを呼ぶ前に、次の情報を記した計画を作る。

| 項目 | 指定すること |
| --- | --- |
| 評価対象 | 評価する Skill のリビジョン。 |
| ファイルのハッシュ | 評価するファイルのハッシュ。 |
| 変更が影響する役割 | Skill が担う作業のうち、変更の影響を受けるもの。 |
| 評価方法 | 選んだ評価方法。 |
| ケースと条件 | 実行するケースと条件の組。 |
| クライアント | 実行に使うクライアント。 |
| モデル | 実行に使うモデル。 |
| サンドボックス | 実行時のサンドボックス。 |
| 呼び出し上限 | モデルを呼ぶ最大回数。 |

### ランナー

このリポジトリには、モデル評価のランナーを同梱していない。\
次に対応するランナーを使う。

- 評価計画。
- 隔離した実行。
- ルーティングの評価で、Skill が読み込まれたことの直接観測。
- 短い評価結果を記録する仕様。

`mtk177a/skills` の `scripts/run_skill_evaluation.py` と、隣接する `evaluation_contract.py` は、対応する実装の 1 つである。\
`--root` でこのリポジトリを指定できる。

計画、実行結果、採点のファイルは、一時ディレクトリに置く。

### 実行

- **呼び出し回数:** モデルを呼んだ回数を確認し、計画外の呼び出しをしない。
- **フィクスチャ:** 使い捨てのフィクスチャでケースを実行する。
- **分離:** 評価対象の Skill を、個人用の同名 Skill や無関係なプラグインから分離する。
- **分離が未確認の場合:** 分離を確認できない実行は、未検証として記録する。

### 採点

選んだケースと条件の組だけを、判定条件に照らして採点する。\
`pass`、`fail`、`inconclusive`、`error` を区別する。

ルーティングの評価では、Skill が実際に読み込まれた記録で判定する。\
最終回答の「Skill を使った」という自己申告を、読み込みの証拠にしない。

### 追加の評価

ケースの追加や再実行は、残っている具体的な不確実性によって判断が変わり得る場合だけ行う。

## 結果を記録する

### 短い評価記録

評価したリビジョンと入力のハッシュを、結果と対応付ける。\
次の情報を含める。

- **終了理由:** なぜ実行を終えたか。
- **未実行のケース:** 実行していないケース。
- **確認できなかった範囲**: 何を検証できていないか。

### 情報の取り扱い

| 記録 | 保存先や扱い |
| --- | --- |
| 合成ケースの ID、件数、判定、ハッシュ、非公開セッションの内容を含まない説明 | 公開する評価記録に含めてよい。 |
| 生の依頼文、出力、実行記録、使い捨てのフィクスチャ | 公開リポジトリの外に置く。 |
| 実際の振り返りで使った非公開の試行証拠やモデル出力 | 公開リポジトリの外に置く。 |

### 操作の権限

評価結果は、次の操作を許可するものではない。

- 提案を承認する。
- 外部のハーネスを編集する。
- Issue に投稿する。
