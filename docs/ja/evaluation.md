# 評価と Skill 監査

これは [`docs/evaluation.md`](../evaluation.md) の日本語参考訳です。\
英語版が正式な方針であり、差異がある場合は英語版を優先してください。

この方針は、このリポジトリが管理する Skill と、振り返りの判断に影響する変更の評価に適用する。\
公開情報と非公開情報の境界に合わせて、[`mtk177a/skills` の Issue #49](https://github.com/mtk177a/skills/issues/49) の変更範囲に応じた評価ルールを導入する。

## 監査の判断

重要な Skill 監査では、対象の版と作業ツリーの状態、期待する動作、利用者とクライアント、指示の所在と権限、観測した証拠、所見、代替案、残る不確実性を記録する。\
責務と範囲、選択条件と他の Skill との併用、指示の優先順位、証拠の質、安全性、コンテキストの負担、移植性、保守性を、その Skill に関係する範囲で確認する。\
英語の正式な Skill と日本語参考訳について、英語版に変更がなくても、意味の対応と日本語の自然さを別々に確認する。\
各論点を `change_required`、`no_change`、`separate_issue`、`unverified` に分類し、重要な所見には証拠、影響、確度、反証できる確認方法を添える。\
文面だけの監査結果を、モデルの実際の動作が確認できた結果として扱わない。

## 評価対象の選び方

ケースを選ぶ前に、変更した責務、起こり得る失敗、その失敗を見つけられる観測を定める。\
判断に必要な最小限の評価を選ぶ。

| 変更 | 基本の評価経路 |
| --- | --- |
| 文書、形式、意味が変わらない文章 | `static-only` |
| Skill の指示、出力の約束、安全上の境界 | `targeted-candidate` |
| 名前、説明、起動条件、隣接する責務との境界 | `targeted-routing` |
| 既知の再発、主要な再設計、候補版だけでは判断しにくい結果 | `baseline-comparison` |
| 特定のクライアントや環境への対応を主張する場合 | `target-environment` |

比較対象、Skill を使わない条件、反復、別のクライアントは、その結果で判断が変わり得るときだけ追加する。\
編集のたびに全ケースを実行しない。\
既存の `evals.json` または `triggers.json` を移行するときは、影響する定義全体を一緒に移す。\
形式だけの移行なら静的な検証を行い、モデル実行は一律に求めない。

## 実行可能な定義

行動のケースは `skills/<name>/evals/evals.json`、選択条件のケースは `triggers.json` に置く。\
Agent Skills の実行可能な形式に従い、`skill_name` と `evals`、ケースの `id`、`prompt`、任意の `files`、`expected_output`、`assertions` を使う。\
選択条件のケースでは `expected_handlers` を使う。\
ケースの依頼文と入力ファイルには、実行側へ見せる情報だけを置く。\
期待結果と判定条件は実行側へ見せず、採点時に使う。\
識別子、リポジトリ、ハーネス成果物、セッションには合成データだけを使い、実セッションは人が秘匿してもコミットしない。\
生の依頼文、出力、実行記録、一時的な入力環境は公開リポジトリの外に置く。
`python3 scripts/check_repository.py` で、管理対象の訳文の組、Skill のメタデータ、実行可能な評価定義、現在の短い評価記録を、モデルを呼ばずに確認する。
同梱の取得スクリプトを変更した場合は、`python3 -m unittest discover -s skills/outer-harness-retrospective/scripts -p 'test_*.py'` を実行し、`skills/outer-harness-retrospective/scripts/retro-pilot` から `go test ./...` を実行する。\
実セッションを読まずに、固定コミットのソースをビルドできることを確認する。

## 実行と記録

モデルを呼ぶ前に、候補版とファイルのハッシュ、変更した責務、評価経路、選んだケースと条件、クライアント、モデル、実行権限、最大呼び出し回数を記した計画を作る。\
このリポジトリにはモデル評価のランナーを同梱しない。\
使用するランナーは、この計画、隔離した実行、Skill 読み込みの直接観測、短い結果の記録に対応する必要がある。\
`mtk177a/skills` の `scripts/run_skill_evaluation.py` と隣接する `evaluation_contract.py` は対応する実装の一つであり、`--root` でこのリポジトリを指定できる。\
計画、実行結果、採点のファイルは一時ディレクトリに置き、そのチェックアウトを試行用補助コマンドの実行時依存に追加しない。\
呼び出し回数を確認し、計画外の呼び出しをしない。\
使い捨ての環境で、評価対象の Skill を個人用の同名 Skill や無関係なプラグインから分離して実行する。\
分離を確認できない実行は未検証として記録する。\
選択条件は、最終回答に書かれた「Skill を使った」という自己申告ではなく、実際に読み込まれた記録で判定する。\
選んだケースと条件だけを判定条件に照らして採点し、`pass`、`fail`、`inconclusive`、`error` を区別する。\
短い結果を評価対象の版と入力のハッシュに結び付け、終了理由、未実行のケース、未確認の境界を記録する。\
追加のケースや再実行は、結果によって判断が変わる具体的な不確実性が残る場合だけ行う。

公開する評価記録には、合成ケースの ID、件数、判定、ハッシュ、非公開セッションの内容を含まない説明を記載できる。\
実際の振り返りに使った非公開の試行証拠とモデル出力は、リポジトリの外に置く。\
評価結果を、提案の承認、外部ハーネスの編集、Issue への投稿の権限として扱わない。
