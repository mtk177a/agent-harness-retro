## ハーネス

### Model

コーディングエージェントが使う言語モデルである。\
OpenAI や Anthropic が提供するモデルなどが該当する。\
モデルそのものはハーネスではない。

### Agent harness

言語モデルをエージェントとして動かすための仕組みである。\
ツール、コンテキスト管理、オーケストレーション、実行環境、メモリなどが該当する。

この語は、次のどちらの層を指すこともある。

| 層 | 管理する主体 |
| --- | --- |
| [組み込みハーネス](#built-in-harness) | コーディングエージェントの提供元。 |
| [外側のハーネス](#outer-harness) | ユーザーやリポジトリの所有者。 |

### Built-in harness

コーディングエージェント製品の一部として、提供元が管理するハーネスである。\
Codex や Claude Code は、モデルの周囲に組み込みハーネスを持つ製品の例である。\
`agent-harness-retro` は、このハーネスを変更しない。

### Outer harness

コーディングエージェント製品と組み合わせて使う、ユーザーが管理する指示や設定などの仕組みである。\
`agent-harness-retro` が振り返る主な対象である。

指示、Skill、Hook、設定、エージェント定義、連携、文書、検証などが該当する。\
それぞれの仕組みの説明は [README](../../README.ja.md#振り返りの対象) を参照する。

### Global outer harness

1 人のユーザーや 1 つの環境で、複数のリポジトリやプロジェクトに使うための外側のハーネスである。

### Repository harness

1 つのリポジトリやプロジェクトが管理する、外側のハーネスである。\
リポジトリの指示、ローカルの Skill、Hook、プロジェクト文書、検証コマンド、テスト、CI などが該当する。

### Harness artifact

外側のハーネスの一部として管理する、個々のファイルや仕組みである。\
更新の基準となるファイルや仕組みを指す。\
指示ファイル、Skill、Hook の設定、設定ファイル、評価資料、リポジトリの検証スクリプトなどが該当する。

### Harness engineering

エージェントハーネスを設計、実装、評価、改善することである。\
組み込みハーネスと外側のハーネスの両方が対象になる。\
`agent-harness-retro` は、その一部として、過去の行動からユーザー管理の外側のハーネスを改善するための振り返りを行う。

## 振り返りの分析

例として、現在のテストガイドに正しいコマンドが書かれている架空のプロジェクトを考える。

| 用語 | 何を説明するか | 例 |
| --- | --- | --- |
| [Observation](#observation)（観測） | 記録から直接、何が分かるか。 | エージェントが `AGENTS.md` に書かれたコマンドを実行し、失敗した。<br>現在のテストガイドには、別のコマンドが書かれている。 |
| [Finding](#finding)（所見） | 証拠が裏付ける問題や有用なパターンは何か、なぜ重要か。 | `AGENTS.md` と現在のテストガイドに異なるコマンドが書かれ、エージェントへの指示が食い違っている。 |
| [Cause hypothesis](#cause-hypothesis)（原因の仮説） | 所見が生じた理由として、何が考えられるか。 | テスト手順が変わった際に、`AGENTS.md` のコマンドを更新し忘れた可能性がある。 |
| [Proposal](#proposal)（提案） | 所有者に、どのような対応を提案するか。 | `AGENTS.md` のコマンドを、テストガイドへのリンクに置き換える。 |

### Retrospective

過去のコーディングエージェントの行動を、範囲を絞って分析し、証拠に基づく外側のハーネスの改善を探すことである。\
振り返りをしても、ハーネスを変更する必要があるとは限らない。

### Session evidence

エージェントの行動を確かめるために使う、共通形式に変換されたセッション記録である。\
`agent-harness-retro` は、提供元固有の記録形式を直接解析せず、`agent-sessions` を通じて取得する。

### Logical lineage

関連するセッションの記録を、再発回数を数えるときに 1 回の発生として扱うためのグループである。

- **同じ参照元**: `source_ref` が同じ記録は、セッションを再開して内容が変わっても、同じ系統に属する。
- **関係のある参照元:** 親や fork の関係が明示されている参照元を、同じ系統にまとめる。
- **再試行:** 同じ系統内での試行の繰り返しは、独立した再発として数えない。
- **不確かな関係:** 必要な関係の証拠が欠けているか曖昧な場合は、その参照元を独立した発生として数えない。

### Observation

正規化済みのセッション証拠や、確認した現在のハーネスの構成要素から、直接分かることを述べたものである。\
解釈や対応案とは分けて扱う。

### Finding

1 つ以上の観測で裏付けられた問題、有用なパターン、結果について、なぜ重要かを説明したものである。\
所見に解決策は含めない。

### Cause hypothesis

所見が生じた理由について、考えられる説明である。\
不確かなものであり、観測とは区別する。

- **支持する証拠:** その説明を裏付ける証拠。
- **反証:** 判断に影響する、説明と食い違う証拠。
- **別の説明:** 判断に影響する、ほかに考えられる説明。
- **不確実性:** まだ分かっていないこと。

### Evidence

所見を裏付けるために使う観測である。

証拠への参照には、次のものがある。

- **参照元と確認した内容**: セッションの参照元と、どの内容を確認したかを特定できる `verified_version`。
- **イベント:** 範囲を絞ったメッセージやツールイベント。
- **ハーネスの構成要素:** 振り返り中に確認した、現在のファイルや仕組み。
- **検証結果:** 決定論的な検査の結果。

### Consumer state

振り返りで得た情報を次回に引き継ぐために、`agent-harness-retro` が非公開で保存する情報である。\
確認した記録を特定する情報、所見、所見と証拠の対応、提案への判断、検証状況などが該当する。\
提供元が管理するセッションデータや `agent-sessions` とは分けて扱う。

現在の Skill は、この情報を保存しない。\
将来追加する可能性がある機能である。\
保存する場合に守る条件は [アーキテクチャ](architecture.md#非公開の振り返り状態) に定めている。

## 対応

### Scope

所見がどこに関係するか、または提案をどこに適用するかを表す。

- **提供元:** 組み込みハーネス。
- **グローバル:** プロジェクトをまたいで共有する外側のハーネス。
- **リポジトリ:** 1 つのリポジトリやプロジェクトが管理するハーネス。
- **個別の構成要素:** Skill や Hook の設定など、ハーネスを構成する 1 つのもの。
- **プロジェクトの実装:** プロジェクト自体のコードや実装。

範囲を検討した結果、恒久的なハーネスの変更は不要と判断する場合もある。\
Scope はどの範囲で対応するか、[Control surface](#control-surface) はどの仕組みで対応するかを表す。

### Control surface

外側のハーネスのうち、エージェントにどう行動するかを示したり、必要な動作を必ず行わせたりする仕組みである。\
指示、Skill、Hook、設定、テスト、CI、文書などが該当する。

### Routing candidate

所見にどう対応するかを検討するときの候補である。\
所見を確認し、どこが対応を担うのか見当をつけてから、候補を比較する。

- **指針:** グローバルな指示やリポジトリの指針。
- **作業手順:** Skill。
- **強制する仕組み:** 決定論的な検査。
- **プロジェクトの変更:** 基準となるプロジェクトの実装や文書。
- **メモリへの引き継ぎ:** 人が検討するための候補であり、自動的にメモリを書き込むものではない。
- **その場限りの対応:** 今回の状況に限った対応。
- **恒久的な変更なし:** ハーネスに恒久的な変更を加えない対応。

詳しい候補と、どの場合に使うかは [Skill の対応手段の一覧](../../skills/outer-harness-retrospective/references/ja/reporting.md#対応の仕組み) に定めている。

### Proposal

1 つ以上の所見に対する対応案である。\
変更先、期待する改善、トレードオフ、変更後に必要な検証を示す。\
提案は、承認済みの変更ではない。

### Decision outcome

所見や対応案を検討した判断結果である。

| 結果 | 意味 |
| --- | --- |
| `proposal` | 所有者に対応案を提案する根拠がある。 |
| `no_change` | 所見の裏付けはあるが、恒久的な対応は不要か、既存の仕組みで十分である。 |
| `reject` | 対応案に反する証拠がある、既存の仕組みと重複する、範囲が不適切である、または変更してよい範囲を超えている。 |
| `insufficient_evidence` | 所見を裏付けたり、必要な判断をしたりするには、証拠が足りない。 |

提案を却下しても、裏付けのある所見は消えない。\
証拠が足りないというだけでは、変更不要とは判断できない。

### Materialization

承認された提案を、実際の外側のハーネスの構成要素に適用することである。\
振り返りの分析とは別の作業であり、ユーザーの明示的な承認が必要である。\
現在の Skill は、提案を適用しない。

### Validation

適用したハーネスの変更が期待どおりに働き、許容できない回帰を起こさないかを確かめることである。\
決定論的な検査や、行動に関する証拠を使う。
