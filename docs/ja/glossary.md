# 用語集

> これは [英語版 `glossary.md`](../glossary.md) の日本語参考訳です。\
> 英語版が正式版であり、内容に差異がある場合は英語版を優先します。

この用語集では、`agent-harness-retro` に固有の用語を定義します。\
これらの用語は、ベンダーが管理するコーディングエージェントシステムと、利用者が管理するハーネス設定を区別するためのものです。

## Model

コーディングエージェントが使う基盤の言語モデルです。\
OpenAI、Anthropic、その他のベンダーが提供するモデル群などが該当します。\
モデルそのものはハーネスではありません。

## Agent harness

モデルにツール、コンテキスト、処理の調整、実行環境、記憶などの制御手段を与え、エージェントとして動作させる仕組みを広く指す語です。\
ベンダーが管理する製品と利用者が管理する層の両方を指し得るため、この区別が重要な箇所では、より具体的な用語を使います。

## Built-in harness

コーディングエージェント製品の一部としてベンダーが提供し、管理するエージェントハーネスです。\
このプロジェクトでは、Codex と Claude Code を、基盤モデルの周囲に組み込みハーネスを持つ製品の例としています。\
`agent-harness-retro` は、ベンダーが管理する組み込みハーネスの内部を変更しません。

## Outer harness

コーディングエージェント製品の周囲に作る、利用者が管理する層です。\
利用者またはリポジトリの所有者が管理する指示、Skills、Hooks、設定、エージェント定義、連携、文書、検証、その他の仕組みを含むことがあります。\
外側のハーネスは、このプロジェクトが振り返る主な対象です。

## Global outer harness

一人の利用者または一つの環境で、複数のリポジトリやプロジェクトに適用することを意図した外側のハーネス成果物です。

## Repository harness

一つのリポジトリまたはプロジェクトに適用する、外側のハーネスの部分です。\
リポジトリの指示、専用 Skills、Hooks、文書、検証コマンド、テスト、CI など、リポジトリが管理するエージェント向けの仕組みで構成されます。

## Harness artifact

外側のハーネスを構成する、基準となる個々の成果物です。\
指示ファイル、Skill、Hook の設定、設定ファイル、評価資料、リポジトリの検証スクリプトなどが該当します。

## Harness engineering

エージェントハーネスの設計、実装、評価、改善を行う活動です。\
`agent-harness-retro` より広い語で、組み込みハーネスと外側のハーネスの両方に適用できます。\
このプロジェクトは、利用者が管理する外側のハーネスを、過去の動作から改善することに焦点を当てます。

## Session evidence

振り返りの証拠として使う、コーディングエージェントセッションから得た正規化済みの観測です。\
`agent-harness-retro` は、プロバイダー固有の生のトランスクリプト形式を直接扱わず、`agent-sessions` を通じてこの証拠を取得します。

## Retrospective

過去のコーディングエージェントの動作を対象とし、根拠に基づいて外側のハーネスを改善する機会を特定する、範囲を限定した分析です。\
振り返りを行っても、ハーネスを変更するとは限りません。

## Observation

正規化済みのセッション証拠、または確認した現在のハーネス成果物が、直接支える記述です。\
観測は、解釈や提案と分けて扱います。

## Finding

振り返り分析によって得た、根拠のある観測です。\
何が起きたと見られ、なぜ重要なのかを記述します。\
提案する解決策とは別のものです。

## Cause hypothesis

所見が生じた理由についての、不確かな解釈です。\
観測と混同せず、支える証拠、重要な反証や別の説明、未解決の不確実性を記録します。

## Evidence

所見を支える観測です。\
セッションの情報源、検証済みの版、範囲を限定したイベント、現在のハーネス成果物、同じ条件で同じ結果を返す検証の結果などを参照できます。

## Proposal

一つ以上の所見に対する、対応の候補です。\
意図する対象、期待される効果、トレードオフ、検証要件を示します。\
承認済みの変更ではありません。

## Decision outcome

所見や候補となる提案に対する、振り返りの判断結果です。\
通常の結果には、提案、変更なし、却下、証拠不足が含まれます。

## Logical lineage

再発回数の計算に使う、一つの対話の系列です。\
同じ論理的な参照元で再開した観測と、明示的な親または fork の関係でつながる参照元は、独立した発生として数えず、同じ系列に属します。

## Routing candidate

根拠に基づく対応の行き先の候補です。\
記憶への引き継ぎ、指示、リポジトリの方針、Skill、同じ条件で同じ結果を返す仕組みによる規則の強制、基準となるプロジェクトの実装や文書、一回限りの対応、永続的な変更なしなどが該当します。\
所見と責任範囲を確定した後に比較します。

## Materialization

承認済みの提案を、実際の外側のハーネス成果物へ適用する行為です。\
実体化は振り返り分析とは別であり、明示的な承認が必要です。

## Validation

実体化したハーネスの変更が、意図した効果を生み、許容できない回帰を起こさないか判断するために使う、同じ条件で同じ結果を返す検査の結果または動作に関する証拠です。

## Scope

所見または提案が適用される層です。

典型的な適用範囲は次のとおりです。

- 組み込みハーネス。
- グローバルな外側のハーネス。
- リポジトリのハーネス。
- 一つのハーネス成果物。
- 基盤となるプロジェクトの実装。
- 永続的なハーネス変更なし。

## Control surface

外側のハーネスの動作を表現または強制する仕組みです。\
指示、Skills、Hooks、設定、テスト、CI、文書などが該当します。

## Consumer state

確認済みの参照元の版、所見、証拠との関係、提案への判断、検証状態など、`agent-harness-retro` が管理する非公開の永続状態です。\
プロバイダーが管理するセッションデータや `agent-sessions` とは分離します。
